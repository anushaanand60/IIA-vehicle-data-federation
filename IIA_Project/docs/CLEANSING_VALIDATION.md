# Cleansing validation (rubric 2)

Generated by `python scripts/validate_cleansing.py --local-db` (seed 20261017, n=300, source: local SQLite copies, 2026-10-17T20:22:32). Deterministic for a given seed and source data.

**Method.** Clean camera captures (registered read; make, model and colour present and agreeing with the registration; parseable timestamp; confidence above the floor; no duplicate, no impossible travel) are sampled with a fixed seed. Each gets one labelled noise type, or none (control). `cleansing.propose` (detection + the RDR tree + the plate matcher) runs on the noisy set in memory, against a Context built from the same snapshot of REG and CAM. Nothing is written to any source. Plate misreads draw their OCR confusions from `data/confusion_costs.json` with the benchmark's own frequencies.

| plate_misread_double | plate_number | `UP16AB0521` | `UP16ABO524` | `UP16AB0524` | R5 | - / I20 / Grey | Hyundai / i20 / Red |

Each row is the matcher ACCEPTing a plate one cheap OCR confusion away from a double misread. The registered colour of the accepted plate contradicts what the camera saw, and the make is not on record, so the context features could not veto it. Proposed remedy (not applied here): an RDR exception under R5 that quarantines a plate correction whose candidate's registered colour disagrees with the observed colour, which needs a colour-agreement feature next to the existing `match_best_make_agrees`.

## Reading the numbers

- A plate the matcher does not ACCEPT is **quarantined**, never guessed: for misreads a quarantine is a safe outcome that counts against correction accuracy but never as a wrong correction.
- `clone_swap` is a valid make and colour of another real vehicle. The right outcome is a FLAG (clone evidence, rule R4); overwriting it with the registered value would destroy the evidence, so any `set` there counts as wrong.
- `low_confidence_corroborated` is expected to raise nothing: low OCR confidence on a read whose make and colour agree with the registration is kept by design (rule R8). Its false-alarm column measures that.
- Timestamps that cannot be read, or postdate the present, cannot be repaired from context, so the expected action is quarantine.
