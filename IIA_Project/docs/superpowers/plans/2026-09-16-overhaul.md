# Federation Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task (Sonnet 5 for tasks marked S, Opus 5 for tasks marked O). Steps use checkbox (`- [ ]`) syntax for tracking. Update this file after every task (tick boxes, add an "Outcome" line) and commit it with the task.

**Goal:** Any record change (SQL console, GUI forms, shell) on any of the 4–5 laptops is visible in the mediator GUI on the next query; the GUI handles unknown plates end-to-end (register → insure → re-evaluate); the UI is restyled on AirSentinel's design system; three field-grounded innovations ship (plate OCR, auto-register workflow, watchlist/risk alerts); the code-quality findings from the review are fixed.

**Architecture:** Unchanged GAV mediator: Streamlit GUI (laptop 1) → mediator (planner → decomposer → executor → integrator → decide) → one FastAPI wrapper per source over HTTP → that laptop's DB. Reads stay on the read-only `/query`; all writes go through each wrapper's `/admin/mutate` (named actions) and `/admin/sql` (guarded free SQL), which are now ON by default. The mediator itself never opens a DB connection to a source.

**Tech Stack:** Python 3.11+, FastAPI, SQLAlchemy, httpx, Streamlit ≥1.57, pytest + `streamlit.testing.v1.AppTest`, EasyOCR (optional, already installed on laptop 1), ReportLab, SQLite/PostgreSQL/MySQL.
