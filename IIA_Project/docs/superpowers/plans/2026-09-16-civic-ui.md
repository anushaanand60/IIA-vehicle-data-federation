# Civic UI Implementation Plan (replaces the AirSentinel skin)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Tick checkboxes as you go.

**Goal:** A single, forced-light, accessible "government platform meets ordinary citizen" interface: sidebar navigation, generous spacing, one neutral base + one high-contrast action colour, every table/button/tab readable regardless of the viewer's OS dark-mode setting.

**Why the last skin failed (from user screenshots):** viewer's OS is dark → Streamlit switched its own base theme to dark (no `base=` in config.toml) while our CSS only partly overrode it → dark tab labels on dark ground, white `st.dataframe` glaring on navy, sidebar unreadable. Also: nine tab labels crammed in one row; hero gradient too dark; density without breathing room.

**Design rules (read these skills first, they override taste here):** `C:\Users\siddh_ygv5bws\.claude\skills\design-taste-frontend-v1\SKILL.md` and `C:\Users\siddh_ygv5bws\.claude\skills\high-end-visual-design\SKILL.md`. Reference model for "civic + accessible": the GOV.UK Design System (do not copy its crown/branding, copy its discipline: black/near-black text on light grey ground, white content panels, one green action button, yellow focus ring, 19px body text, generous vertical rhythm, labels above inputs, hint text below labels, error text in red with a left bar).

**Tech:** Streamlit 1.57 only. No new deps.

**What the visual pass changed.** Four defects were only visible once the pages were rendered:
the sidebar brand block ran its two lines together (inline spans), the decision banner came out
plain white because the legacy `.fm-banner` base rule was emitted *after* the variant tints and
won the cascade, number inputs and text areas showed one stray edge instead of a border (baseweb
puts the border on its root element, not the `<input>`), and `st.info` drew its bar beside the
text rather than at the container edge. All four are fixed in commit 6, along with
`color-scheme: light only` so a browser cannot auto-darken the page.

**Notes / deviations:**
- Headless screenshots could not be taken with `--screenshot --virtual-time-budget`: virtual time
  expires before Streamlit's websocket has rendered anything, so every frame was the loading
  skeleton (itself drawn in the OS's colour scheme, which is very likely what the user first saw).
  The shots are taken with Selenium + Edge instead, waiting for `.cv-pagehead` and for the skeleton
  to disappear. The driver script lives in the session scratchpad, not in the repo.
- The sidebar group headings (Enforcement / Citizens / Mediator) are drawn with `::before` on the
  1st, 5th and 6th nav items rather than as separate markdown blocks, because the menu must stay a
  single `st.radio` for exactly-one-page-open semantics. Reordering `PAGES` in `app/app.py` means
  reordering those `nth-of-type` rules in `app/theme.py`; both sides say so in a comment.
- `TOKENS` carries the plan's palette verbatim plus the ten status/decision names the app already
  uses (`ok/timeout/down/error`, `clear/report/alert/…`), each mapped onto one of the five status
  colours. `alert` is the only new hex: the gravest verdict gets a darker red than `report`.
- `panel()` opens a *keyed* container and the stylesheet targets `[class*="st-key-cvp_"]`. In
  Streamlit 1.57 `stLayoutWrapper` is emitted for every container, column and expander, so the
  test id suggested in the plan could not be used without boxing the entire page.
- Captions are `ink2`, not `ink_muted`: `ink_muted` only just clears AA and read washed out in the
  rendered page.
- `tests/test_executor.py::test_unparseable_wrapper_response_is_error` failed once in a full run
  mid-task and passes in isolation and in the final run — a pre-existing socket race in the
  transport tests, untouched by this work.
- Edge's *opt-in* `WebContentsForceDark` feature still inverts the rendered pixels (no page can
  override a post-render filter), but the computed background stays `rgb(243,244,246)` and the
  result is uniformly dark and legible — not the half-light/half-dark page that was reported.
