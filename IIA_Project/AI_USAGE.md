# How AI was used in this project

This is a disclosure and reproduction guide for the teaching assistants. It records which parts of
Project A (Uninsured Vehicle Identification) were built with an AI coding assistant, what we asked
it, what it produced, how the output was checked, and how to reproduce everything from this
repository.

## 2. Division of work

**What the team did without AI.** The base commit `cfef269` ("base commit", by a teammate) holds the
team's own first version: the four source schemas, synthetic data generators (`reg.py`, `ins.py`,
`theft.py`, `cam.py`, `puc.py`), a first mediator (`mediator/matcher.py`, `decomposer.py`,
`integrator.py`, `decide.py`, `transforms.py`, `planner.py`, `catalog.py`), wrappers and a Streamlit
GUI. The project brief, the design document and the choice of a federated mediator came from the
team.

**What the humans did throughout.**

- Wrote every prompt in `docs/ai/PROMPTS.md` and chose what to build next.
- Made the design decisions when asked, for example: keep Streamlit, commit to `main` in small
  verified commits, include all proposed innovation features, reject the first two UI designs.
- Installed PostgreSQL and MySQL on three physical laptops, loaded the data, opened firewall ports,
  and ran the cross-laptop tests. The AI could not reach those machines. Errors were pasted back as
  prompts, which is why several prompts are terminal output.
- Reviewed screenshots and behaviour, and reported what was wrong.

**What the AI did.** Everything in the commits listed in section 4: 87 commits, 167 files changed,
about 27,500 lines added and 900 removed, measured with `git diff --shortstat cfef269 HEAD`.

**About commit authorship.** The commits carry the student's git identity (`Kalki-06`) and no
AI co-author trailer, at the student's request. This document is the disclosure instead. Every
commit by `Kalki-06` from `b87e32e` (15 Sep) to the latest was generated by Claude Code during the
sessions whose prompts are in `docs/ai/PROMPTS.md`. Commit timestamps can be matched against prompt
timestamps there.

## 3. How the AI was used

The same loop was used for every piece of work:

1. **Prompt.** A request in plain words, often with pasted errors or screenshots.
2. **Investigate.** Read-only sub-agents surveyed the relevant code and reported findings, before
   anything was changed.
3. **Plan.** For large work, a written plan with exact files, interfaces, tests and acceptance
   checks, saved under `docs/superpowers/plans/`.
4. **Build.** Coding sub-agents worked on separate files in parallel, test-first: write a failing
   test, see it fail, write the code, see it pass, commit.
5. **Verify.** The full test suite, the ground-truth evaluation (621 plates) and the matcher
   evaluation were run before every push. UI changes were checked with headless browser screenshots.
   Demo commands were run against a live local cluster before being written into guides.
6. **Report.** A summary back to the humans, including what could not be verified. Real PostgreSQL
   and MySQL across laptops, for example, was verified only when the team ran it.

Constraints given to the AI and followed throughout: never push to the teammates' repository from
the private combined copy; keep a rollback tag (`before-sql-console`); no AI trailer in commits;
the mediator never copies source data and never writes through its read path.

## 4. Phase by phase

Prompt numbers refer to `docs/ai/PROMPTS.md`.

**Prompts 1–5.** Build the transport layer from our brief (`CLAUDE.md`) and the design PDF, then merge

**Built.** `mediator/contract.py` (typed request and response models), `mediator/registry_loader.py`,

**Built.** `STUDY_GUIDE.md`; three study pages published privately on claude.ai (not part of the

## 6. Reproduce it

### 6.1 The code and its results

Windows PowerShell, Python 3.12:

```powershell
git clone https://github.com/anushaanand60/IIA-vehicle-data-federation.git
cd IIA-vehicle-data-federation\IIA_Project
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

python scripts\load_source.py REG
python scripts\load_source.py INS
python scripts\load_source.py THEFT
python scripts\load_source.py CAM
python scripts\load_source.py PUC
python scripts\seed_mappings.py
python scripts\seed_challan_cases.py --reset
```

Check the numbers quoted in our report and demo:

```powershell
python -m pytest -q                                          # 672 passed, 3 deselected
python scripts\evaluate_ground_truth.py --start-wrappers     # 621/621 = 100.0%
python scripts\evaluate_matcher.py                           # OVERALL precision 1.00, recall 1.00
```

Run the system on one machine:

```powershell
python scripts\configure_cluster.py --local
python run_system.py                                         # http://localhost:8501
```

The multi-laptop setup with real PostgreSQL and MySQL, and a step-by-step test of every feature, are
in `docs/DEMO_GUIDE.md`.

### 6.2 The AI process

Language model output is not deterministic, so the same prompts will not produce byte-identical
code. What can be reproduced or inspected:

- **The requests:** `docs/ai/PROMPTS.md`, in order.
- **The design decisions and acceptance criteria:** the three plans in `docs/superpowers/plans/`.
  Each lists files, interfaces, tests, and an Outcome section recording deviations.
- **The exact result of each step:** `git show <commit>` for any commit in section 4.
- **The checks:** the test suite and the two evaluation scripts above.

To replay a phase with Claude Code, check out the commit before it, open Claude Code in
`IIA_Project/`, give it the plan file for that phase, and ask it to execute the plan task by task.

## 7. Limits of the AI's work

| Area | Limit |
|---|---|
| Real laptops | the AI could not reach the team's laptops; PostgreSQL and MySQL across machines was verified by the team, not by the AI |
| Admin write API | no authentication: it has a statement guard, a table whitelist and a separate owner account; a real deployment would add a login |
| Data | synthetic, from seeded generators; plates and stories are planted for the demo |
| Challan Guard | corrects one misread character per plate; travel speed uses straight-line distance; fine amounts follow one section of the Motor Vehicles Act |
| Earlier mistakes | caught and fixed along the way, each visible in git history. Examples: a Streamlit double-import crash (`74d37ee`), a dark-mode UI that the team rejected (replaced by `54b695e`), a case selector that reset after Verify (`c3a3678`), owner-account writes on real databases (`e45769c`), a blank form field breaking onboarding (`f69f725`) |
